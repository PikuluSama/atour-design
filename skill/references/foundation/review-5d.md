# 基座 #9 · 5+1 维评审

> 触发:Ed 说「评审」「打分」「review this design」「好不好看」。对已有设计(eds-design 产出或外部来源)做结构化评审。

## 维度 0 · 概念/立意(权重最高,一票否决)

先问「这个设计有没有一个 idea」,再看做得好不好。执行是放大器——放大一个空洞的概念只会更空洞。

| 分数 | 标准 |
|---|---|
| 9-10 | 从内容里长出来的独有 idea,视觉母题不可替换 |
| 7-8 | 有明确立意,母题与内容相关但换个近似主题勉强能用 |
| 5-6 | 只有风格没有概念:好看,但没说任何东西 |
| 3-4 | 通用模板套皮,概念层为零 |
| 1-2 | 连风格都没选对,纯装饰堆砌 |

**核心问题**:这个设计说了什么?一句话讲得出 idea 吗?盖住所有文字和 logo 还认得出主题吗?换个客户名还成立吗?(成立 = 模板,本维度 ≤5)

🔴 **一票否决**:概念 ≤5 分时,**总评封顶 6.0**——后面维度全是 execution,再精致也拉不回一个没有 idea 的设计。

## 维度 1-5(执行层)

| 维度 | 核心问题 | 关键检查 |
|---|---|---|
| 1 哲学一致性 | 是否贯彻所选设计哲学 | 标志性手法到位?有无自相矛盾元素?(选原研哉却塞满内容 = 矛盾) |
| 2 视觉层级 | 视线是否沿意图流动 | 标题正文对比 ≥2.5 倍;3-4 个清晰层级;「眯眼测试」层级仍清晰 |
| 3 细节执行 | 做工是否精良 | 对齐/间距一致性、字距行距、边缘处理、无烂尾元素 |
| 4 功能性 | 能否完成实际任务 | 可读性底线、交互完整性(对照 `engineering-checklist.md`) |
| 5 创新性 | 有没有让人记住的点 | 至少一处「值得截图」的 120% 细节;不是套模板 |

## 输出格式

1. **雷达图**(6 维,HTML/SVG 渲染)
2. **Keep**:做对了要保持的(具体到元素)
3. **Fix**:必须修的(按严重度排序,给修法)
4. **Quick Wins**:低成本能显著提升的
5. **总评** + 一句话定性

## 场景侧重点

- 原型:功能性、细节执行权重升
- 封面/卡片:概念、视觉层级权重升
- 动画:细节执行(节奏/缓动)、概念权重升
- 信息图:功能性(信息传达准确)、层级权重升
