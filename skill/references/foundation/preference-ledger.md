# 基座 #10 · 偏好账本协议(自进化)

> 来源:乔木设计顾问的自进化机制 + Ed's OS 的 Loop 自主权分级。目标:**Ed 的每一次反馈都沉淀成规则,eds-design 越用越懂 Ed。**

## 触发:什么时候记

- Ed 给出**明确反馈**:「以后别用紫色」「封面要更克制」「原型密度太高了」
- Ed 的**选择行为暴露偏好**:三方向里总选某一类、总是要求同一类修改
- **重复出现的修改模式**:同一项目里第二次提出同类修改 → 该成规则了

## 流程:反馈 → 规则 → 归位 → 回写

1. **识别**:这条反馈是偶然还是偏好?偶然的(「这次亮一点」)不记;模式性的记
2. **抽象成规则**:写成可执行的句子,带适用条件。
   - ❌ 「Ed 喜欢克制」(不可执行)
   - ✅ 「公众号封面默认 VARIANCE ≤5,禁用渐变,标题用思源宋体」(可执行)
3. **判断归属**:
   - **项目级**(只适用于某项目/品牌)→ 写入该项目的 `.eds-design/profile.md` 的 `ledger` 段
   - **通用级**(跨项目的品味)→ 写入 `preferences/preference-ledger.md`(中央账本)
4. **回写前向 Ed 复述一遍规则**(Tier1:自干但进评审队列)——「我记下这条:……,以后都按这个来,OK?」Ed 点头才落盘;Ed 修正就按修正版落
5. 落盘时标注日期与来源(「2026-08-07,三方向选择反馈」)

## 🔴 隔离铁律

**品牌/雇主相关的任何规则、偏好、资产只写入对应项目的 `.eds-design/profile.md`**——绝不写入中央账本、skill 目录或其他位置。判断标准:这条规则离开该项目语境还成立吗?不成立 → 项目级。

## 读取:账本优先

每次任务开始、偏好探测时,**先读账本再读 profile 其他内容**——账本是 Ed 的最新判断,覆盖 profile 里的静态描述;两者冲突时账本赢,并提醒 Ed 更新 profile 正文。

## 规则格式(账本条目,采用 P-编号制)

```markdown
### P-{编号} · {规则一句话}
- 级别:硬禁令 / 强偏好 / 情境规则
- 何时适用:{范围与条件}
- 原话摘录:「{Ed 当时的表述}」
- 收录:{日期}｜来源:{三方向选择/明确反馈/重复修改}｜状态:生效 / 已废止({日期,原因})
```

示例:

```markdown
### P-3 · 公众号封面禁用渐变与插画风
- 级别:硬禁令
- 何时适用:20-Create 所有封面;改用冷色 + 大字标题
- 原话摘录:「封面要更克制,别花里胡哨」
- 收录:2026-08-07｜来源:封面三方向选择｜状态:生效
```

**级别语义**:硬禁令 = preflight 必查项;强偏好 = 默认遵守、Ed 明说可破;情境规则 = 仅在注明的场景生效。

## 边界

- 账本只记**偏好与规范**,不记事实(事实归 product-facts.md)、不记项目数据(数据归项目自己)
- Ed 说「这条作废」→ 条目加删除线保留痕迹,不物理删除(可追溯)
