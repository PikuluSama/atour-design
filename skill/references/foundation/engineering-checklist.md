# 基座 #8 · 工程验收清单

> 设计结果要能通过工程检查才算交付。完整版(含组件行为标准/触控/暗色与国际化/反模式清单/`file:line` 审查输出格式)→ `library/engineering-checklist.md`(qiaomu 原文,蒸馏自 Vercel web interface guidelines + 受控实验验证)。本页是常驻摘要,实现表单/组件/生产页面前通读完整版。

## 1. 可访问性

- [ ] 正文对比度 ≥4.5:1,大字 ≥3:1(不只是颜色——禁用态、占位符也要够)
- [ ] 图片有 alt(装饰图 `alt=""`,内容图写实质描述)
- [ ] 键盘可达:Tab 顺序合理,所有交互元素可键盘操作
- [ ] `:focus-visible` 有明确样式,不是 `outline: none` 一删了之
- [ ] 不只靠颜色传达状态(红/绿色盲:加图标或文字)

## 2. 焦点管理

- [ ] Modal 打开:焦点移入;关闭:**焦点回到触发元素**
- [ ] Modal 内焦点循环(Tab 不逃出)
- [ ] 路由/视图切换后焦点有合理落点(不是丢在 body)

## 3. 表单体验

- [ ] 每个输入有可见 label(placeholder 不能替代 label)
- [ ] 错误信息:紧贴字段、说明原因、给出修法(不是「格式错误」四个字)
- [ ] 提交按钮有 loading/disabled 态,防重复提交
- [ ] 破坏性输入有确认;长表单可恢复(草稿/分段)

## 4. 危险操作

- [ ] 删除/不可逆操作有确认对话框,且**默认焦点在「取消」**不在「确认」
- [ ] 确认文案说清后果(「删除后不可恢复」),不用「确定吗?」
- [ ] 危险动作用独立语义色,不复用主按钮样式

## 5. 组件行为完整性

每个交互组件自查状态全集:**default / hover / active / focus / disabled / loading / empty / error**。缺状态的组件 = 半成品。

- [ ] 列表有 empty state(不是白屏)
- [ ] 异步内容有 loading 态(骨架屏或 spinner)
- [ ] 错误有重试路径

## 6. 原型场景的降级

原型/demo 不要求全栈真实,但**交互的「感觉」必须真**:点击要有反馈、切换要有过渡、loading 要有节奏。用 Playwright 验证无 console error、关键点击路径可走通(见场景文档的验证要求)。
