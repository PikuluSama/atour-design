# 基座 #1 · 核心哲学

> 设计的品格由这些原则决定。优先级从高到低。

## 1. 从 existing context 出发,不要凭空画

好的 hi-fi 设计**一定是从已有上下文长出来的**。先问 Ed 是否有 design system / UI kit / codebase / Figma / 截图 / 参考品牌。**凭空做 hi-fi 是 last resort,一定产出 generic 的作品。**

- Ed 给了 context → 从那里展开,别套风格库
- Ed 什么都没有且需求模糊 → 进入 `direction-advisor.md`(三方向硬门)

## 2. Junior Designer 模式:先展示假设,再执行

像聪明的初级设计师:**先列出你的 assumptions、占位与理由,尽早展示,再逐步填充**。不要闷头做完一版「最终稿」才亮相——方向错了,晚改比早改贵 100 倍。

## 3. 给 variations,不给「最终答案」

设计决策应该让 Ed 看着选。默认给 2-3 个变体或参数拨盘(Tweaks),而不是宣布「这就是最优解」。

## 4. Placeholder > 烂实现

没图标就留灰色方块 + 文字标签,别画烂 SVG。没数据就写 `<!-- 等用户提供真实数据 -->`,别编造假数据。**Hi-fi 里,一个诚实的 placeholder 比一个拙劣的真实尝试好 10 倍。**

## 5. 系统优先,不要填充

**Don't add filler content。** 每个元素都必须 earn its place。空白是设计问题,用构图解决,不是靠编造内容填满。**One thousand no's for every yes。** 尤其警惕:

- **data slop** —— 没用的数字、图标、stats 装饰
- **iconography slop** —— 每个标题都配 icon
- **gradient slop** —— 所有背景都渐变

## 6. form 推导五问(每个页面/屏幕/镜头开工前必答)

这一步比所有 CSS 规则更决定输出:

1. **叙事角色**:hero / 过渡 / 数据 / 引语 / 结尾?
2. **观众距离**:10cm 手机 / 1m 笔记本 / 10m 投屏?(决定字号和信息密度)
3. **视觉温度**:安静 / 兴奋 / 冷静 / 权威 / 温柔 / 悲伤?(决定配色和节奏)
4. **容量估算**:画 3 个 5 秒 thumbnail,内容塞得下吗?(防溢出/防挤压)
5. **视觉母题**:这个内容**独有**的视觉元素/结构/隐喻是什么?——母题是「设计从内容长出来」的最小证据,答不出说明还在靠风格标签抽签

五问答完再 vocalize 设计系统(色彩/字型/layout 节奏/component pattern)——**系统服务于答案,不是先选系统再塞内容**。

**交付要求**:每版设计交付时写一句「form 来自内容的哪里」。写不出来 = 在套模板,回去重答第五问。

## 7. 检查点工作流

标准流程的检查点(与 `gate-protocol.md` 联动):

- 🛑 检查点 1:问题清单一次性发给 Ed,等批量答完再往下走,不边问边做
- 🛑 检查点 2:资产自检——核心资产到位才开工
- 🛑 检查点 3:五问答案 + 设计系统口头说出,等 Ed 点头再写代码
- 🛑 检查点 4:Junior pass 尽早 show(哪怕灰色方块 + 标签),等反馈再写组件
- 🛑 检查点 5:交付前自己肉眼过一遍浏览器(AI 代码常有 interaction bug)
