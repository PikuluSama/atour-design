# 基座 #4 · 设计方向顾问(三方向硬门)

> 🔴 **100% 硬门**:任何会产出新视觉设计的任务,无一例外——需求模糊触发、需求清晰也触发、Ed 指定了风格(「Apple 宣传片风格」「Stripe 那种感觉」)**同样触发**、给了品牌名/品牌资产**同样触发**。先提供三个差异化方向(含**真实初稿**),Ed 选定后才进入执行。

## 根本立场

skill 的职责是**帮 Ed 规避最差的设计**——守住反 slop 下限,**不是规定「好设计长什么样」**。真正的好设计**从 Ed 的需求和内容里长出来**:

- Ed 给了内容/品牌/参考 → 从那里展开,**别套库**
- Ed 什么都没有 → 三套逻辑只是帮他**起步、打破惯性**的脚手架,不是终点
- 风格库是「没思路时翻的弹药」,**不是必须从中选的清单**

## 为什么指定风格也不豁免

「Apple 风格」是一个**语境**不是一个设计:深空暗场、大白底衬线、产品色沉浸都是合法诠释,选哪个是 Ed 的权利。**风格词收窄解释空间,不转移选择权。**

- 指定风格时的三方向 = 该风格语境内三个差异化诠释
- 给品牌名时的三方向 = 三版全部基于同一套品牌资产,差异在设计诠释

## 唯一豁免(仅此三种,全部落档 direction-approved.md)

1. Ed **本次会话明说**跳过(「不用出三版」「直接做」「就按上次那个方向」)
2. **已选定方向后的迭代**(同项目改稿、加镜、换素材——方向已是 Ed 选的)
3. **非设计的机械操作**(HTML 转 PDF、导出、截图、修 bug、纯文字改动)

## 三方向初稿形态(必须是看得见的真实视觉,不是文字描述)

| 产物 | 每方向交付 |
|---|---|
| 网页 / 信息图 / 原型 | 1 个完整 HTML + 截图 |
| 多页 deck | 2 页代表页(兼作 showcase) |
| 动画 / 宣传片 | 1 张「方向板」:hero 关键帧真实静帧截图 ×1-2 + 色板条 + 一句气质定位 + 参照作品名(❌ 不是三支成片) |
| 封面 / 单图 / 社交卡片 | 1 张真实出图 |

## 流程(7 Phase)

1. **对话澄清 + 主动索要参考**(一次最多 3 问):受众/核心信息/基调/格式 + 项目叫什么/有无 logo 品牌色/有无喜欢的参考。⏱️ Ed 不回应 → 按 best judgment 补假设(标 assumption),直接做完三版摆出来,**用看得见的东西代替追问**
2. **顾问式重述**(≥200 字):嚼透本质需求、潜在期待,以「我直接做 3 个不同方向的真实版本给你看」结尾
3. **固化设计 spec**(≥500 字):三个 subagent 的唯一共同输入。必含:产品是什么、受众场景、核心信息分点、情感基调、**输出格式与尺寸(三版必须统一)**、约束、图片需求、视觉母题假设、三拨盘读数
4. **3.5 图片素材前置**:图片内容必需?→ 先取齐真图(公共领域库/Unsplash/品牌资产协议)再 spawn;具名产品逐个取 logo(base64 内嵌);取图失败三级兜底,降级继续不卡死
5. **三套逻辑并行 subagent**(独立 context、互不参考、共用 spec 与真图):
   - 🎲 **秒数轮盘**:`date +%S` % 20 + 1,从风格库对应半区取风格——强制打破「每次偷选安全极简」
   - 🏆 **现实参照**:选 1 个真实存在的获奖网站/模板(WebSearch 核实),拆解迁移
   - 🧠 **最佳设计师**:假设预算无上限,最适合的工作室/设计师(Pentagram/原研哉/…),启用其设计哲学
6. **Ed 基于真实视觉选择**:深化 / 混合(「轮盘版配色 + 设计师版布局」)/ 微调 / 全部重来。选定后立刻写 `direction-approved.md`(Gate 协议)
7. **进入主干执行**:回 Junior Designer pass 把选定版做扎实

## 执行规范

- 用 Ed 的**真实内容**(非 Lorem),三版同内容只换设计逻辑
- **三版布局骨架必须互异**——不许共用骨架只换色换字体(换皮会被一眼识破)
- 🔴 **轴级差异纪律**(qiaomu 实测:无此纪律时模型会用表面差异冒充多样性):方向差异必须至少覆盖三条轴中的两条——**字体家族轴**(衬线↔无衬线↔等宽↔展示体)、**色彩体系轴**(明↔暗、中性↔高饱和、单色↔多色)、**布局结构轴**(对称↔非对称、卡片↔分隔线↔纯留白、居中↔编辑网格)。强制自检:**遮住颜色,三个方向还能被区分吗?** 不能就重来
- **互斥约束分配**(Design It Twice):给每个方向分配一条互斥硬约束再开工——如 A「必须亮色印刷质感」/B「必须暗色高密度」/C「必须借非数字时代的视觉语言」——从机制上杜绝趋同;并行 subagent 时约束写进各自任务书
- 深度发散方法 → `library/divergence-playbook.md`
- 🔴 **可读性硬底线**:正文 ≥14px、标签 ≥12px、对比度 ≥4.5:1;留白是构图不是内容缺席
- 存项目目录 `design-demos/`,❌ 禁 `_temp/`
- ✅ 自检:`design-demos/` 下必须真有 **3 个**产物,少于 3 个补齐再往下
- **展示后必须停**:结束回合等 Ed 选择,不得自行选定继续(autonomous 会话也一样)

**选择无效铁律**:绝不让 Ed 在「只有文字、没看到视觉」时选风格——他没有依据。

**可选增强 · 交互式试衣间**:Ed 要求「弹个页面让我选」或方向较多需精细对比时,走 qiaomu 风格试衣间规范 → `library/style-preview.md`:生成 `design-previews/YYYY-MM-DD-任务名/index.html` 自包含预览页(4 方向 2×2 网格 + 三拨盘滑块 + 确认弹层),可启动 `scripts/qiaomu-design-preview-server.mjs` 本地回传服务(127.0.0.1,选择结果写 `selection.json`)。服务起不来就降级为截图 + 对话选择,不阻塞。默认流程仍是截图 + 对话选择——试衣间是增强,不是必经。

**弱 runtime(不支持 subagent)**:改串行跑三套——每套开跑前只读 spec、清空上一套记忆、用不同 anchor 物理隔离趋同。串行也**必须出三版**。

完整 40 风格库 → `references/library/design-styles.md`(Phase 2 迁入)。
