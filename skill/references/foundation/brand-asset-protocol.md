# 基座 #6 · 品牌资产协议

> **资产 > 规范。** 品牌的本质是「它被认出来」。这是稳定性的生命线——走通本协议,输出质量是 90 分;跳过,是 40 分。

## 触发条件(两类都算,第二类最常被漏)

1. **为某个品牌做物料**(发布动画、落地页、PRD 原型……)
2. **设计里要呈现一个或多个真实可识别的产品/品牌**——对比/榜单/评测/介绍 deck、信息图里点名某产品

🔴 **铁律:设计里只要出现一个能被认出的产品/品牌名,它的官方 logo 就是必需资产**(出现几个就取几个),不是「有就用、没有拉倒」。即使走三方向 Fallback 也不豁免——Fallback 决定「用什么视觉风格」,不豁免「取齐具名产品的 logo」。

**前置**:先通过 `fact-verification.md` 确认品牌/产品存在且状态已知。

## 识别度排序(为什么资产 > 规范)

| 资产类型 | 识别度贡献 | 必需性 |
|---|---|---|
| **Logo** | 最高 | **任何品牌都必须有** |
| **产品图/渲染图** | 极高 | **实体产品(硬件/包装/消费品)必须有** |
| **UI 截图/界面素材** | 极高 | **数字产品(App/网站/SaaS)必须有** |
| 色值 | 中 | 辅助(脱离前三项经常撞衫) |
| 字体 | 低 | 辅助 |
| 气质关键词 | 低 | agent 自检用 |

**违反本协议的行为**:只抽色值字体不找 logo/产品图;用 CSS 剪影/SVG 手画替代真实产品图;找不到资产不告诉 Ed 硬做。

## 5 步硬流程(每步有 fallback,绝不静默跳过)

1. **问**:资产清单一次问全(logo/产品图/UI 截图/色板/字体/guidelines),有的直接发,没有的去搜抓
2. **搜官方渠道**:官网 / press kit / 官方社媒 / Wikimedia;logo 走 svgl API → simpleicons → Google favicon 三级兜底
3. **下载资产**:用 `scripts/fetch_images.py`(清代理 + 合规 UA + 许可输出)或按类型兜底路径
4. **提取**:色值从真实 HTML/SVG/官方页抽取(不凭印象),固化 CSS 变量
5. **固化 brand-spec.md**(Gate 文件):logo 路径/base64、产品图、色值表、字体、气质关键词、禁区

## 交付内嵌规则

**交付形态是「双击就能开」的单文件 HTML 时,logo/图片必须 base64 内嵌**——相对路径的交付物挪个目录就全员裂图(盲测实锤:`../assets/google.svg` 六个按钮全裂直接输掉评审)。仅多文件 + 启动说明的项目允许本地路径。

## 具名产品 logo 子门(spawn 三方向前必过)

把设计里会出现的产品/品牌名**逐个列成清单**,确认每个都已取到官方 logo 并内嵌。**清单里有一个没取到 = 🛑 STOP 补齐**(实在取不到才退诚实 placeholder 并明说「X 的 logo 待补」)。对比/榜单/评测 deck 最常见的翻车点:「只抽了品牌色就开做」。

## 普通主题 ≠ 品牌

「咖啡/鹦鹉/历史/健身」是**内容主题**,不是可找 logo 的品牌——不要跑去找「咖啡的 logo」空转。主题类内容走 direction-advisor 的取图策略(公共领域库/Unsplash)。
